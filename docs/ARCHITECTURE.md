# ARCHITECTURE

本文件面向需要理解或修改 LexiGrab 的开发者，说明系统由哪些部分组成、一次查词如何流动、边界在哪里。组件清单与阶段状态见 [ROADMAP](../ROADMAP.md)，接口字段见 [BACKEND_STRUCTURE](BACKEND_STRUCTURE.md)，agent 实现细则见 [PROMPT](../PROMPT.md)。

## 1. 总览

LexiGrab 由一个常驻托盘的桌面应用和一个 Firefox 扩展组成。桌面应用负责词典、缓存、语境辅助与 Anki；扩展只负责网页里的选区、句子和页面信息，再通过本机 HTTP 桥接请求桌面端。

```text
┌──────────────────────────── Windows 桌面应用 ────────────────────────────┐
│  WebView 窗口：管理器 / 划词弹窗 / 设置                                  │
│        │ Tauri IPC                                                      │
│  Rust 命令层 ── 查询调度 / 语境辅助 / Anki / 桥接 ── 本地与远程词典源    │
│        │                                  │                            │
│  SQLite（缓存与同语境指纹）         mdx-res 资源协议（图片/音频）         │
└───────────────────────────────┬─────────────────────────────────────────┘
                                │ 127.0.0.1 + X-Auth-Token
                     ┌──────────▼──────────┐
                     │ Firefox 扩展        │
                     │ content / background│
                     └─────────────────────┘
```

## 2. 分层

**界面层。** 三个独立窗口共享组件与 IPC 类型：管理器负责词典源和查询测试，弹窗负责一次查词与制卡，设置负责热键、主题、Anki、扩展、缓存和语境辅助。窗口由 Rust 侧预创建，避免在命令线程里创建 WebView 阻塞事件循环。

**命令层。** 每个 Tauri Command 只做参数整理、错误转换和阻塞边界，业务逻辑放在 `core`、`sources`、`parsers`、`anki`、`db`。这样 CLI 与桥接可以复用同一套逻辑，而不依赖 WebView。

**核心层。** `AppState` 是唯一状态中心，持有配置、源注册表、缓存、卡片指纹和查询元数据。查询调度决定本地同步返回、缓存命中与远程后台任务；远程结果通过事件追加，不阻塞首屏。

**数据源与解析器。** 数据源回答“从哪里取”，解析器回答“怎样变成统一词条”。两者正交：新增一种词典格式不需要改查询调度，新增一个数据源也不需要改界面。

**平台层。** Windows 选区捕获、光标定位和非激活弹窗通过 Win32 与 UI Automation 实现。其他平台保留接口，不承诺功能。

## 3. 一次桌面查词

1. 全局热键触发选区捕获，拿到选中词、可选原句和光标位置。
2. 弹窗在光标附近显示，但不抢走原应用焦点。
3. 前端调用查询命令，命令把工作交给查询调度。
4. 调度器按优先级查询本地源与缓存；远程源按策略同步或转入后台。
5. 本地结果立即返回；远程结果与失败通过事件更新同一个弹窗。
6. 有原句且启用语境辅助时，后台请求选择器；低置信度再按配置请求 LLM。
7. 用户确认词、释义、原句和来源后保存到 Anki；同词同句同释义只提示，不阻断。

## 4. 浏览器链路

content script 在页面中读取选区、定位块级上下文并切句，渲染 Shadow DOM 气泡；网络请求与配对令牌只存在于 background。background 调用桌面端的 `/v1/selection`、`/v1/sense` 与 `/v1/anki`。桥接只监听回环地址，并按令牌、Origin 与限流校验。

浏览器无法读取应用内的本地词典资源，因此桥接返回的释义会先剥离本地图片与音频。远程资源仍以普通 URL 返回。

## 5. 数据与文件

- 配置与日志位于用户应用数据目录，可用 `LEXIGRAB_HOME` 指向便携目录；`LEXIGRAB_CONFIG_DIR` 可单独覆盖配置目录。
- SQLite 同时保存查询缓存、语境缓存和同语境卡片指纹；缓存可清理，卡片指纹不随查询缓存清空。
- 本地词典图片/音频通过 `mdx-res` 协议读取，路径与 MIME 都受白名单限制。
- 扩展的配对信息保存在 Firefox 扩展存储中，不写入页面。

## 6. 边界

- 只承诺 Windows 与 Firefox；其他平台和浏览器保留扩展点，不作为 0.1.0 验收项。
- 远程词典、选择器和 LLM 都是可选增强，失败只影响自身，不阻断本地结果。
- AI 释义是候选，不是词典事实；必须标注模型并经用户采用后才能写卡。
- 桥接不绑定局域网地址，不信任代理头；日志不记录令牌或完整原句。
- 不引入组件库、状态管理库、路由库或远程字体，保持构建与分发简单。

## 7. 修改入口

需要动手时先看 [PROMPT](../PROMPT.md) 的代码地图、任务配方与验证矩阵。新增契约先改 [BACKEND_STRUCTURE](BACKEND_STRUCTURE.md) 或 [APP_FLOW](APP_FLOW.md)，再改实现；完成一个阶段后更新 [PROGRESS](../.agents/plans/PROGRESS.md)。
