# PRD

本文件定义 LexiGrab 0.1.0 的产品范围、用户故事与成功标准。技术架构与里程碑的原始约定见 [PROMPT.md](../PROMPT.md)，不在本文件重复。界面与交互的逐屏路径见 [APP_FLOW.md](APP_FLOW.md)，视觉主参考见 [figma.md](../.agents/design/figma.md)。

## 1. 产品定义

LexiGrab 是一个 Windows 优先的桌面划词查词工具。用户在任何应用或浏览器里选中一个词，用一次快捷键得到释义，并把词、释义、原句和来源写入 Anki。

它解决三个具体问题：

1. 查词要切换窗口、打开网页、复制粘贴，打断阅读。
2. 本地 MDX 词典、远程词典服务、浏览器划词工具各自为政。
3. 制卡要手动搬运词、释义和原句，原句经常丢失。

产品形态是常驻托盘的小工具，不是词典阅读器，也不是完整的 Anki 客户端。

## 2. 目标用户

| 用户 | 场景 | 关键诉求 |
| --- | --- | --- |
| 语言学习者 | 阅读外文网页、PDF、电子书、聊天记录 | 不打断阅读，快速看释义，顺手制卡 |
| Anki 用户 | 已有牌组与笔记模板 | 字段能对上，原句和来源不丢，重复可控 |
| 词典收集者 | 手上有多个 MDX/MDD 词典 | 一个工具挂多个词典，支持优先级与同时查询 |
| 自建服务用户 | NAS 上有自己的词典 API | 能配置 URL、鉴权和响应解析 |

## 3. 产品目标

1. 把“选词到看到释义”的路径压缩到一次快捷键。
2. 本地词典直接读取，不要求用户启动额外服务。
3. 远程词典与本地词典统一呈现，远程失败不打断本地体验。
4. 制卡保留词、释义、原句、来源四类信息，并允许提交前编辑。
5. 浏览器场景通过扩展获得可靠的原句，不依赖桌面端的猜测。
6. 所有网络能力可审计、可关闭，默认只监听本机回环地址。

## 4. 范围

### 4.1 0.1.0 包含

- Windows 10/11 桌面端，Tauri 2 + React。
- 全局快捷键触发划词弹窗，默认 `Ctrl+Shift+D`。
- 本地 `.mdx` / `.mdd` 读取，一个源可挂多个文件，多源查询。
- 查询策略：`local_first`（默认）、`first_hit`、`aggregate`。
- 远程 HTTP 词典：URL 模板、固定鉴权头、JSONPath 解析、JavaScript 脚本解析。
- AnkiConnect 制卡：牌组、笔记类型、四字段映射、标签、同词多卡与同语境提示。
- 提交前编辑原句与释义源码，预览释义。
- 桌面端尽力而为的句子捕获；失败时保留编辑入口。
- 语境辅助：JEV-like 本地选择器先按原句选义项并给出置信度；低置信度时由可选 LLM 生成语境释义，结果必须标注来源，不静默覆盖词典。
- 同一单词允许建立多张卡片：按原句/义项区分；Anki 层允许重复，应用层只对“同词同句同释义”提示。
- 词典源管理、运行状态、查询测试。
- 设置：通用、Anki、语境辅助、浏览器扩展、缓存、关于。
- Firefox 扩展：划词、原句提取、页面信息、本地桥接查询与制卡。
- 本地 HTTP 桥接：`127.0.0.1`、`X-Auth-Token`、Origin 校验、限流。
- SQLite 查询缓存，默认 24 小时 TTL，负缓存 5 分钟。
- 中文界面，AGPL-3.0 开源。

### 4.2 0.1.0 不包含

- macOS、Linux 的正式支持与验收。目录与平台抽象保留，功能不承诺。
- Chrome、Edge、Safari 扩展。WXT 工程保留多浏览器构建能力，只验收 Firefox。
- AMO 发布与自动签名。`.xpi` 采用本地/自行分发。
- Anki 媒体上传。制卡时剥离本地图片与音频，保留占位文本。
- 卡片 URL 字段。四字段契约不包含页面链接。
- 云同步、账户、遥测、崩溃上报。
- 自动更新、代码签名证书、应用商店分发。
- 词典阅读模式、生词本、复习调度、发音服务、OCR、PDF 内嵌阅读器。
- 脚本的可视化调试器或包管理。
- 多语言界面。文案集中管理，英文以后再加。
- 自动保证义项判断正确。选择器与 LLM 都是辅助，用户保留最终选择权。
- 把 LLM 输出当作权威词典内容，或未经用户确认自动写卡。
- 以“单词唯一”为前提的去重。同一单词在不同语境下必须可以保存多张卡。

## 5. 用户故事

### US-01 即时查词

作为阅读者，我在任意应用选中单词后按一次快捷键，希望 200ms 内看到弹窗和释义，并且原应用不失去焦点。

验收：

- 记事本、Chrome、Firefox、VS Code 中选中英文单词，热键触发弹窗。
- 弹窗出现在选区附近，双屏与 150% 缩放下不越界。
- 点击弹窗按钮时，原应用仍保持前台焦点。
- 没有选中文本时，弹窗显示可重试的错误，并允许手动输入。

### US-02 本地词典

作为词典收集者，我希望把多个 `.mdx` 挂到同一个源，并能调整源的优先级。

验收：

- 支持多选文件，同名 `.mdd` 自动加载。
- 一个源内多个词典的查询结果合并展示。
- 源可启用/禁用、重命名、调整顺序、删除配置而不删除文件。
- 大词典加载不冻结界面，失败有错误摘要。

### US-03 制卡

作为 Anki 用户，我希望在弹窗里确认词、释义、原句和来源后一键写入牌组。

验收：

- 默认字段为 Word、Definition、Sentence、Source。
- 牌组、笔记类型、字段映射来自全局设置。
- 原句与释义可编辑，保存前能看到预览。
- 聚合查询时来源为命中源名称，逗号分隔。
- 同词同句同释义已有卡片、Anki 未运行、字段缺失有可读提示，输入不丢失。

### US-04 远程词典

作为自建服务用户，我希望配置一个非标准 API，并用 JSONPath 或脚本把它映射成词条。

验收：

- URL 模板包含 `{word}`，支持固定鉴权头与超时。
- JSONPath 模式支持标准响应契约。
- 脚本模式接收 `responseBody` 与 `query`，返回词条数组。
- 脚本超时或报错时该源视为无结果。
- 远程超时、500 或断网不影响本地结果。

### US-05 浏览器原句

作为网页阅读者，我希望在 Firefox 里划词时自动带上当前句子、页面标题和 URL，而不是靠桌面端猜。

验收：

- 扩展捕获词、原句、URL、标题、域名。
- 原句来自选区所在块级元素，超长时按句切分。
- 结果在页面内气泡展示，不跳转、不刷新。
- 保存到 Anki 走本地桥接，扩展不直接访问 AnkiConnect。

### US-06 配对与安全

作为注重隐私的用户，我希望浏览器扩展只能通过带令牌的本机接口访问桌面端。

验收：

- 桥接只监听 `127.0.0.1`，不绑定局域网地址。
- 所有请求校验 `X-Auth-Token`。
- 令牌可显示、复制、轮换，轮换后旧令牌立即失效。
- 非 `moz-extension://` Origin 被拒绝。

### US-07 设置与恢复

作为用户，我希望修改热键、主题、查询策略和缓存，而不必手改配置文件。

验收：

- 热键冲突时不写盘并保留旧热键。
- 主题切换立即生效。
- 缓存可查看占用并清空。
- 配置损坏时自动备份并以默认配置启动。

### US-08 离线与失败

作为用户，我希望网络或 Anki 出问题时仍然能用本地词典。

验收：

- 远程失败静默降级，不弹阻断模态框。
- 缓存命中时显示结果并标记来源。
- Anki 不可用时给出安装/启动指引，不丢输入。
- 配置、日志、缓存位置可在关于页打开。

### US-09 语境义项选择

作为阅读者，我希望工具结合原句，从词典的多个义项中推荐当前语境最可能的一个；如果没有任何义项贴合，能明确告诉我并给出可选的 AI 释义。

验收：

- 有原句时，JEV-like 选择器收到词、原句与候选义项，返回所选义项与 0–1 置信度。
- 高置信度：推荐义项高亮，保存默认使用该义项；全部义项仍可查看。
- 中置信度：显示“建议确认”，不自动改用户选择。
- 低置信度或无匹配：显示“可能不在词典义项中”，并调用已启用的 LLM 生成语境释义。
- AI 释义有明显标记、模型名与“可能不准确”提示；用户点击“使用此释义”后才进入制卡。
- 选择器、LLM 超时或失败不阻塞原始词典结果。
- 没有原句时不做自动选择，只展示全部义项。

### US-10 同词多卡

作为 Anki 用户，我希望同一个单词在不同句子、不同义项下分别建卡，而不是被“重复卡片”拦住。

验收：

- 同一单词 + 不同原句可以连续保存为多张卡。
- 同一单词 + 同一原句 + 不同义项/释义也可以保存为多张卡。
- AnkiConnect 请求始终允许重复；应用层只对“同词同句同释义”给出一次性提示，用户可继续保存。
- 保存成功后弹窗不立即关闭，提供“再存一张”与“换义项”入口。
- 不同语境不因为首字段相同被应用层拦截。

## 7. 约束与依赖

- 平台：Windows 10/11，WebView2。
- Anki：AnkiConnect 插件（代码 `2055492159`），默认 `http://127.0.0.1:8765`。
- 浏览器：Firefox 109+，扩展未签名，目标用户使用 Developer Edition/Nightly 或临时加载。
- 本地服务：仅回环地址，固定端口默认 12787。
- 语境选择器：可选，JEV-like 本地 HTTP 服务，默认 `127.0.0.1:8787`；不启用时只展示全部义项。
- LLM：可选，OpenAI-compatible 接口；默认走本机端口，远程端点必须显式允许；API key 只从环境变量读取，不写入配置。
- 隐私：只有启用语境辅助且存在原句时，才把词、原句与候选义项发送给选择器/LLM；前者默认回环，后者默认关闭。
- 许可证：AGPL-3.0，不允许不兼容 copyleft 依赖。
- UI：主参考 [figma.md](../.agents/design/figma.md)；布局与断点按 figma，apple/cursor 只提供可替换配色主题，详见 [FRONTEND_GUIDELINES.md](FRONTEND_GUIDELINES.md)。

## 8. 关键决策

| 决策 | 结论 | 原因 |
| --- | --- | --- |
| 句子捕获 | 桌面尽力而为，浏览器完备 | 跨应用可靠捕获成本高，扩展有 DOM 上下文 |
| 本地 API | localhost HTTP + 令牌 | 比 Native Messaging 部署简单 |
| 远程解析 | JSONPath + 脚本双模式 | 覆盖标准与非标准 API |
| 缓存 | SQLite，24h | 断网可用，减少远程压力 |
| 查询策略 | 三种，默认 local_first | 本地优先，远程异步补全 |
| 分发 | 未签名安装包 + 未签名 .xpi | MVP 不承担签名基础设施 |
| 媒体 | 展示但不写入 Anki | 四字段契约下先保证文本正确 |
| 语境选择 | JEV-like 本地选择器 + 置信度，LLM 仅在低置信度兜底 | 词典只给义项，不给语境判断 |
| AI 边界 | AI 释义只作为候选，必须标注模型并手动采用 | 避免把生成内容伪装成词典原文 |
| 多卡片 | Anki `allowDuplicate: true`，应用层只提示同语境重复 | 同一单词在不同语境下本就应该多卡 |
| 去重键 | 词 + 规范化原句 + 规范化释义的指纹 | 首字段相同不再等于重复 |
